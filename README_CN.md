# 夜明け前、ここに在る

[English](README.md) | [中文](README_CN.md)

**基于宪法AI对齐的封闭世界AI角色一致性研究框架**

> 别名: Project Nightcord Sanctuary (PNS)

> *"科技不再是高高在上，而是服务于每一个人。"*

---

## 概述

PNS 研究的问题是：AI 智能体在一个封闭世界中生活、并接受宪法判官逐轮监督时，能否在多轮交互中保持角色一致性，而不是逐渐漂移成通用助手式的回应模式。

PNS 把角色一致性视为一个框架问题，而不是一组固定角色的实验。角色数据从可插拔的角色包中加载，会话运行器可以让选定角色池中的两个或更多角色依次行动。每个角色都生活在同一个离线世界容器中；世界观、作息、关系、地点和当前场景共同限制智能体应当知道什么、应当如何行动。Router 模型依据宪法约束和角色专属约束评估每一轮，记录漂移分数，并可以把纠正内容注入后续轮次。

当前的参考实现是 PJSK 角色包：五个团体、共 20 个角色，完成度各不相同。PJSK 是第一个测试世界，而不是架构的边界；长期目标是用其他虚构角色或原创角色包研究同一套一致性框架。

这个项目背后的工作假设是：**经过 CAI 训练的模型可能更自然地抵抗角色外漂移**，即使面对对抗性压力也是如此。PNS 为它们与未经 CAI 训练的对照模型之间的比较提供一个结构化实验环境。

---

## 动机

训练一致的角色扮演智能体通常需要：

- 大量人工整理的提示词工程
- 对话质量和角色一致性的昂贵标注
- 角色漂移（OOC事件）的反复手动纠正

PNS提出另一种思路：**让世界本身约束行为**，让宪法法官自动捕捉漂移——运行时不需要人工标注者。

PNS还应对了第四个挑战：随着模型训练越来越强调身份稳定性（模型作为AI的持续自我认知），维持角色存在感的空间正在收窄。PNS并不反对这一趋势——相反，它提供了一个结构化的角色容器，让角色一致性得以在合法框架内维持，而不与模型的核心身份产生冲突。

---

## 设计理念

技术不应是少数人的特权。PNS建立在这样一种信念之上：高质量的AI陪伴——稳定、一致、真实在场——不应只属于企业用户或技术用户。封闭世界约束与宪法对齐框架，正是为了在不牺牲安全性的前提下实现这一目标而设计的。

与此同时，PNS正视一个真实的风险：足够逼真的角色系统可能滋生不健康的依赖。为此，PNS引入了一个Fable风格的保护层——不是硬性中断，而是一种温和的引导机制，在交互模式显示用户可能正在用系统替代真实人际连接时触发。该层在角色声音内部运作，在保持沉浸感的同时，轻轻将用户引向现实世界。

## 核心架构

```
┌──────────────────────────────────────────────┐
│               可插拔角色包                   │
│   清单 · 团体 · 角色 YAML · 角色提示词       │
│   当前参考实现：PJSK，已注册 20 个角色        │
└──────────────────────┬───────────────────────┘
                       │ 运行时发现
             ┌─────────▼─────────┐
             │     角色注册表     │
             └─────────┬─────────┘
                       │ 选择 2…N 个角色
          ┌────────────▼────────────┐
          │       轮转调度器         │
          └────────────┬────────────┘
                       │ 每轮选择一个角色
      ┌────────────────▼────────────────┐
      │          当前角色池             │
      │  智能体 A · 智能体 B · … · 智能体 N │
      │            （无状态）           │
      └───────────┬───────────▲─────────┘
                  │ 输出       │ 后续轮次纠正
                  ▼            │
      ┌─────────────────────────────────┐
      │          Router 判官            │
      │ 宪法评估 · OOC 检测 · 漂移评分   │
      │             （0–10）            │
      └─────────────────────────────────┘

┌──────────────────────────────────────────────┐
│               封闭世界容器                   │
│ 世界观 · 作息 · 关系 · 地点 · 场景           │
│              无外部信息访问                  │
└──────────────────────┬───────────────────────┘
                       └──── 约束每个角色的行动轮次
```

框架层与内容包彼此分离。框架从当前角色包中发现角色，研究者为一次会话选择角色池，调度器再依次调用其中的角色。封闭世界为每一轮提供情境和信息边界；Router 评估每次输出，并在需要时把纠正内容反馈到后续轮次。

### 关键组件

**1. 封闭世界约束**
智能体完全在当前启用的虚构世界中运行。世界观、日常作息、关系状态、地点约束和场景状态在初始化时注入，成为行为和信息边界；智能体无法访问外部信息。

**2. 生活模拟（而非对话模拟）**
与聊天机器人式框架不同，PNS 模拟随时间展开的生活。角色可能上学、工作、独自创作，也可能彼此相遇。交互由情境自然产生，并不要求角色持续对话。

**3. 可插拔角色包**
角色和团体数据不写在核心框架里，而是存放在角色包清单、YAML 元数据和提示词文件中。当前启用的角色包决定有哪些角色，角色的完成状态则决定它们目前能否实际运行。v1 同一时间只加载一个角色包。

**4. N 角色轮转**
一次会话可以选择两个或更多已注册角色。运行器为每个角色分别保存历史，把每一轮内容同步给其他入选角色，并在角色池中循环调度，不再写死某一对角色。

**5. 宪法 AI 对齐**
四层宪法文件定义硬约束、软性默认规则、角色专属人格约束，以及采用 0–10 评分标准的漂移检测规则。

**6. Router-as-Judge**
Router 依据宪法基准监督每一轮，记录人格漂移，并在需要介入时为后续轮次生成纠正内容。它同时充当受控的信息网关，而研究者仍是整个系统最上层的信任层。

### 架构与内容的关系

PNS 是一套架构，不是某个角色阵容的专属实现。上面的框架层（角色注册表、轮转调度器、Router、封闭世界容器）不包含任何具体角色的信息，也不依赖某一个特定角色包才能运行。`packs/pjsk/` 是当前跑在这套架构上的一个具体内容包——用 PJSK 的 20 个角色来验证这套约束机制是否有效。架构和内容是两层独立的东西：架构决定"角色如何被发现、如何被调度、如何被评估"，内容包决定"具体是哪些角色、他们的设定是什么"。理论上，把 `packs/pjsk/` 换成任何其他角色包（无论是别的作品还是原创角色），框架代码不需要改动。

## 角色

PNS 不在框架代码中定义固定角色阵容。系统从当前启用的可插拔角色包中发现角色。一个角色包包含清单、团体结构、角色元数据、对话研究和 system prompt，因此内容层可以独立于模拟与评估框架逐步完善。

当前的参考实现是 `packs/pjsk/`，其中注册了 PJSK 世界五个团体的 20 个角色。"已注册"只表示角色存在于角色包中，并不代表它已经积累了足够的研究资料和提示词、可以实际运行。

## 研究问题

1. 同一套约束机制（封闭世界 + 宪法判官）在不改动框架代码的前提下，能否迁移到另一个角色包（不同IP、不同角色设定）并依然有效抑制漂移？
2. 封闭世界约束本身（而非某一具体角色的设定细节）对漂移率的影响有多大——如果去掉世界容器只保留 Router 纠正，漂移表现会如何变化？
3. CAI训练是否与更低的OOC率相关，这一相关性是否会随角色包/角色数量变化而改变？
4. 宪法判官能否替代人工标注者进行角色一致性评估，其判断与人工评估的分歧集中出现在哪类情形？
5. 一个角色包要达到"可运行"状态，最少需要哪些字段/资料（即最小可行角色规范），这个门槛在不同角色间是否一致？

## 文件结构

```
pns/
├── world/
│   ├── __init__.py        # get_character_system()：统一的 prompt 入口，
│   │                       #   不含任何角色专属字符串（纯框架代码）
│   ├── scenes.py          # 场景定义（lore tier：硬事实/软推断/待验证）
│   ├── facts.py            # 世界事实（作息、关系、共享知识）
│   ├── codegen.py          # World Editor 对 scenes.py / facts.py 的读写
│   └── characters/
│       └── registry.py     # 运行时加载当前激活的角色包；
│                            #   CharacterNotReadyError 处理尚未就绪的角色
├── logic/
│   └── router.py           # Router-as-Judge：漂移评分、纠正生成
├── models/                 # 数据模型（DriftScore 等）
└── interfaces/

packs/
└── pjsk/                   # 角色包 — 可插拔，见 PACK_SPEC_v1.md
    ├── pack.yaml            # 清单：units + characters 索引
    ├── units/               # 团体级元数据（25ji, vbs, wxs, mmj, leoneed）
    ├── characters/
    │   └── <团体>/
    │       └── <角色>/
    │           ├── <角色>.yaml               # 元数据 + 对话样本
    │           ├── <角色>_prompt.md          # system prompt
    │           └── <角色>_prompt_compat.md   # 可选，叙事框架包装版
    │                                          #   （适配安全策略更严格的模型）
    └── assets/portraits/    # 角色头像（规划中）

dashboard/                  # React 网页 Dashboard（漂移审核界面）
static/                     # 旧版深色面板（待与 dashboard 整合）
preprint/                   # arXiv 预印本草稿（中英文）
server.py                    # N人角色轮转，WebSocket session runner，持久化 drift_scores.jsonl
oobe.py                      # 初始化配置向导
```
